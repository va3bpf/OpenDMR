# Languages: the design

[中文](i18n.md)

The firmware has English only. Another language is made of two kinds of file, both written to the radio by the CPS:

- **A language file** (`<code>.json`): the interface strings, one file per language, a few KB
- **A font file** (`<name>.bin`): the glyphs the firmware's own fonts do not have, for example the Chinese font
  `cjk.bin`, about 2.6 MB

Once written, the language is chosen in Options → Language. Adding a language is adding a language file, with no new
firmware; a font file is needed only for a new script (Korean, Japanese, …). Fonts are kept apart from languages: the
one Chinese font serves the Chinese interface and the Han characters of channel and contact names too, with the
interface in English as well.

## 1. The language file

UTF-8 JSON, edited by the translator:

```json
{
  "format": 1,
  "code": "zh",
  "name": "中文",
  "english_name": "Chinese",
  "font": "cjk",
  "strings": {
    "TEXT_LANGUAGE_NAME": "中文",
    "TEXT_MENU": "菜单",
    "TEXT_ZONE": "区域"
  }
}
```

| Field | Meaning |
|---|---|
| `format` | Version of the file format, 1 today |
| `code` | Language code (ISO 639-1, with a region when needed, e.g. `pt-BR`), at most 7 bytes; writing the same code again replaces it |
| `name` | The name in the language's own script, shown in the menu |
| `english_name` | The English name, shown in the CPS, and in the radio's menu when the font is not installed |
| `font` | The font it needs; left out by languages drawn with the firmware's glyphs (ASCII, Latin-1) |
| `strings` | The strings: the keys are the `TEXT_x` names of `src/ui/text/text.h` |

- **English is the reference**: `tools/text/languages/en.json` has every key; `tools/text/gen_text.py` makes
  `text.h`, `text_en.c` and the key table (section 3) from it. English is built into the firmware, the default and
  the fallback of the strings another language lacks.
- A missing string is shown in English; an unknown key (one removed from the firmware) is ignored. So firmware and
  language files of different versions work together.
- The format specifiers (`%d`, `%s`, …) must be the same, in the same order, as in English. The CPS checks before
  writing, the firmware checks again when it reads; a string that differs is shown in English, so a bad file cannot
  break the radio.
- `tools/text/check_lang.py <code>.json` is for translators: missing strings, wrong specifiers, strings too wide in
  the firmware's fonts.
- The Chinese and Spanish of today become `zh.json` and `es.json`, released with the firmware (GitHub Release and
  `dist/languages/`).

## 2. The font file

The Roboto fonts of the firmware have ASCII and Latin-1 (the accented letters of Spanish, French, German,
Portuguese, …) in 9 sizes; those languages need no font file. Other scripts come in font files:

| Font | What | Size |
|---|---|---|
| `cjk` | All of GB2312 (17 px), level 1 (32 px bold), the GB2312 → Unicode table (codeplug names) | 2.63 MB |
| Korean (later) | The 2350 common syllables, 17 px | about 330 KB |
| Japanese (later) | About 1000 Japanese-only kanji, 17 px (the kana are in `cjk`) | about 140 KB |

Made by `tools/fonts/mkfont_pack.py` (from `mkcjk.py`). Format, little endian:

```
0   "DM32FNT1"
8   u32 file length
12  u32 CRC-32 from byte 64 on
16  char name[8] (ASCII, NUL padded, e.g. "cjk")
24  char language[8] (optional: the language these glyphs are for, e.g. "ja" for Japanese kanji)
32  u8 number of fonts, 3 bytes padding
36  u32 offset of the GB2312 table (0: none)
40  u32 offset of the font table
44  reserved up to 64
font table: per font { u32 offset, u16 glyph count, u8 pixel size, u8 bold }, no limit on the number
each font and its glyph compression as in today's cjk.bin (mkcjk.py)
```

## 3. String numbers

Language files use names, the radio uses numbers. So that the CPS need not know the firmware's numbers, and versions
can be mixed:

- Each key name is hashed (FNV-1a, 32 bit); the flash holds the hash and the string
- `gen_text.py` builds a table of `{hash, number}` sorted by hash into the firmware (about 2.6 KB), and checks that
  no two keys share a hash
- Reading a language, the firmware looks each string up in that table to get its number; unknown ones are skipped
- The `TEXT_x` numbers may change from one firmware to the next; the CPS only computes hashes

## 4. The external flash

The Chinese font area of today (0x280000–0x630000, 3.69 MB) is split:

| Address | What |
|---|---|
| 0x280000–0x2A0000 | Languages: 8 slots of 16 KB |
| 0x2A0000–0x2A1000 | Font directory |
| 0x2A1000–0x630000 | Fonts (3.55 MB: Chinese 2.63 MB, about 0.9 MB left) |

**A language slot** (16 KB, with its own header, no directory):

```
0   "DM32LANG"
8   u32 length
12  u32 CRC-32 from byte 16 on
16  char code[8]
24  char name[32] (UTF-8, in its own script)
56  char english_name[24]
80  char font[8]
88  u16 number of strings, 2 bytes padding
92  number x { u32 hash, u16 string offset from the slot start }
    then the strings, UTF-8, NUL terminated
```

The CPS writes the rest of the slot first and the page holding the header last: cut half way, the slot has no valid
header and is not used. Deleting erases its first sector.

**The font directory** (one sector):

```
0   "DM32FDIR"
8   u8 count, 3 bytes padding
12  up to 16 x { char name[8], u32 address, u32 length, u32 CRC-32 }
```

The CPS writes a font in free space, then the directory. Deleting changes only the directory.

## 5. Firmware

- English only is built in (`text_en.c`); `text_zh.c` and `text_es.c` go
- When a language is chosen (at power-on and in the menu), its whole slot (16 KB) is read into RAM, with a u16
  offset per string. The specifiers are compared with English string by string. `text()` still
  returns a `const char *`; its callers do not change
- The language is stored as its code, not a number: the codeplug custom data block "DT" 8 (0x44540008: version 1,
  3 bytes padding, `char code[8]`). At power-on, a language no longer there means English
- Compatibility: without "DT" 8, "DT" 4 is read (a number: 1 Chinese, 2 Spanish), and without it `bitfield_options`
  bit 19 set means `zh`; choosing `zh` still sets bit 19, and "DT" 4 follows when it is there
- Without its font a language's strings show "??", which says the font is missing
- The language menu: English and the installed languages, each by its own name; by its English name when its font
  is not installed
- Glyphs: first the Roboto of the firmware, then the font of the current language, then the other fonts (directory
  order). Chinese and Japanese share the Han code points, so the current language's font comes first and a Japanese
  interface shows Japanese forms
- GB2312 names: the first font with a table
- No more limit of 4 fonts (`font_cjk.c` becomes the font directory and several fonts)

## 6. CPS

- The release zip has a `languages` folder: `zh.json`, `es.json` and `cjk.bin` (for Chinese), the files as they are.
  On the CPS's Languages page the user chooses that folder (a page opened from disk cannot read the files beside it);
  Chinese and Spanish are ticked, the user only presses Write; untick what is not wanted
- Fonts go by name: a language file's `font` is the name in the font file's header. When a ticked language needs a
  font neither in the radio nor chosen, the page says so, and asks again before writing
- A new "Languages" page: the languages in the radio (code, name, strings, how many missing) and the fonts (name,
  size), and the space left
- **Add a language**: pick a `.json`. Checks the format, the specifiers, the size (a 16 KB slot); says so when the
  font it needs is missing, and lets the font file be picked with it
- **Add a font**: pick a `.bin`, check its header and CRC, write it in free space, update the directory
- **Delete** a language or a font; deleting the current language turns the radio to English
- Writing: an `'X'` sector number with the top bit (0x800000) set is a raw address of the external flash; the
  firmware allows only 0x280000–0x630000. The usual parts and CRC read-back (`writeVerifiedSector`, `sectorCrc`)
- Afterwards the radio reads the language area and the font directory again, with no restart
- `tools/fonts/upload_cjk.py` and the debug command `'D' 'F'` are no longer needed

## 7. Upgrading

The old `cjk.bin` (`DM32CJK2`) is no longer read. Chinese users coming from an older version write `cjk.bin` and
`zh.json` once with the CPS; until then the interface is in English and Chinese names cannot be shown. The release
notes must say so.

## 8. Names in the codeplug

Channel, zone and contact names are GB2312, 16 bytes: enough for Chinese, English and Japanese kana, and left as they
are for now. Korean names wait for another encoding (for example the codeplug marked as UTF-8, the CPS converting);
in UTF-8, 16 bytes hold only 5 Korean or Han characters, which the interface and the CPS must say.

## 9. Right-to-left scripts

Arabic and Hebrew run right to left, and Arabic letters change shape with their place in the word. Not now, but kept
possible: all text goes through one function (`font_draw_text()`), where the bidirectional order and the shaping
can go later; mirroring the screens is another step.

## 10. Steps

| Step | What |
|---|---|
| 1 | Tools: `en.json` as the reference, `zh.json`, `es.json`; `gen_text.py` makes the key table; `check_lang.py`; `mkfont_pack.py` |
| 2 | Firmware: language area, font directory and several fonts, the language stored as a code, the menu, raw writes with `'X'`; English only built in |
| 3 | CPS: the Languages page, writing and deleting languages and fonts |
| 4 | On the radio: English → write Chinese → Spanish → delete → write cut by power-off; remove `upload_cjk.py` and `'D' 'F'` |

## How to help

- **Translate**: copy `en.json`, change `code`, `name`, `english_name` and the strings, run
  `py tools/text/check_lang.py`, fix what it lists, write it to the radio with the CPS, look at every screen, and open
  a PR to `develop` (the file goes in `tools/text/languages/`)
- **Code**: say so in an issue before starting, so work is not done twice
- In the PR, say which screens you checked on the radio
