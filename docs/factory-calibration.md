# 出厂校准表

原厂在产线上用 CPS 的 **Test Mode**（隐藏的工厂校准窗口）调每台电台，结果写在数据 Flash（25Q128）里的一个 4 KB 扇区。
本固件只读不写（`services/factory_cal.c`，菜单「校准」显示）。

下面的 layout 是 2026-11-11 用绿色那台对出来的：刷回原厂固件 DM32.01.L01.048，读 Test Mode，把每一行的数值在这台的扇区备份里
搜（每行都只有一处匹配），再和橙色那台（25DM32025845）的扇区比较。

## 扇区在哪里

在 0x1000 ~ 0xC9000 之间按 4 KB 扇区找：最后一个字节是 0x02，并且 0x300 / 0x328 的第一个频率分别落在 UHF（380 ~ 480 MHz）
和 VHF（130 ~ 180 MHz）里。码表数据也可能以 0x02 结尾，所以频率检查不能省。**每台机器的地址不同**：绿色 0xC0000，橙色
0xAA000。菜单「校准」第一行显示找到的地址。

## 本固件用到的项

**每台不同的字节全部都用到了。**菜单「校准」的「晶振微调」一行显示 TX / RX 两个值。

### 4FSK

0x017（UHF）/ 0x0A6（VHF）写进 `RF_MOD_BIAS_CTRL` 的低半字，高低两个字节都写同一个值（`drivers/modem.c`
`modem_set_frequency_calibration()`）。进入 DMR 收发时由 `HRC7000SetDMRModemCalibration()` 写入。

频点之间和功率表一样线性插值、四舍五入，校准点上就是表里的值；低于第一个点、高于最后一个点用两端的值，不外推。
（以前用 1/f：一个波段内 `频率 × 值` 的平均除以频率，波段两头差 1 ~ 2，例如绿色 VHF 136 MHz 算出 238，表里 240。）

### RX Freq Adjust

0x027 写进 `RF_MOD_BIAS_CTRL` 的高半字。以前用 `TX Freq Adjust + 384` 算：绿色 111 + 384 = 495、橙色 110 + 384 = 494，
两台都碰巧对；但另一台截图里是 113 和 495，按公式是 497，差 2。现在直接读，只有表里这两个字节是 0x0000 或 0xFFFF 时
才用公式。

### 没用的

都是两台一样的默认值，不是逐台校准的，所以不用：

| 项 | 本固件 | 不用的原因 |
|---|---|---|
| Analog Mode | FM 发射频偏用固定值（`FM_DEV_COEF`、FD6818 0x40） | 不知道原厂怎么把它写进寄存器；UHF 后两个点是 80、VHF 是 255，像没填。频偏要准，先用综测仪量 |
| SQ9 / SQ1 Open | 静噪按固定刻度（`radio.c` `squelch_level()`） | 不知道原厂和哪个读数比；窄带 400 的 SQ9（17 ~ 21）比 SQ1（19 ~ 23）还低，不合理 |
| RSSI 1 / 4 | S 表用自己的换算 | 只有两个点；S 表要准，用信号源实测 |
| Low Volt、Battery Adjust | 自己的低电报警和「电池校准」 | 不需要 |
| 频段上下限 | 自己的频段表 | 不需要 |
