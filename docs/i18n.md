# 多语言设计

[English](i18n.en.md)

OpenDMR 的界面现在有英文和中文。这份文档是加更多语言的设计和分工，给想帮忙翻译或改代码的人看。原则只有一条：
**加一种语言不能去掉另一种**，所有语言一起编进固件，用户在“选项 → 语言”里选。

## 1. 语言编号

- 每种语言一个编号：0 英文、1 中文、2 西班牙文……，新语言按顺序往后加，编号不改。
- 编号存在码表里 OpenDMR 自己的自定义数据块（类型 0x44540004，“DT” 4），和按键映射（“DT” 2）一样。设置结构
  `settings_t` 要和 OpenGD77 的格式一致（108 字节），里面没有空位。
- 兼容：没有这个数据块时，`bitfield_options` 第 19 位为 1 是中文，为 0 是英文（现在的存法）。选中文时照旧置
  第 19 位，别的 CPS 看到的结果不变。
- 语言菜单列出所有语言，每种用自己的文字写名字（`TEXT_LANGUAGE_NAME`：English、中文、Español……）。某种语言的
  字形没有装（见第 3 节），菜单里显示它的英文名。

## 2. 文字表

- **英文是基准**：`src/ui/text/text.h` 的 `TEXT_x` 是全部文字的编号，英文表必须每条都有。
- **每种语言一个源文件**：`tools/text/languages/<代码>.txt`，UTF-8，一行一条：

  ```
  TEXT_MENU_ZONE = 区域
  TEXT_UI_TX_TIMEOUT = 发射超时
  ```

  比 OpenGD77 那种 windows-1252 的 C 头文件好改，不用会写 C。现有的语言文件转成这个格式。
- **`tools/text/gen_text.py` 生成 `src/ui/text/text_<代码>.c`**，并检查：
  - 缺的条目写 NULL，运行时 `text()` 显示英文，新加的 `TEXT_x` 不会变成空白；脚本列出各语言缺了哪些
  - 格式符（`%d`、`%s`……）和英文的一样多、一样顺序，否则报错
  - **宽度**：按固件的字体量出每条文字画出来的宽度，超过它在界面上的位置（列表行名、值、底栏按键……）就报出来。
    超宽的文字要改短，不能靠界面截断（截断以后看不出意思）
- 全部语言编进固件：一种语言约 7 KB，固件还有约 340 KB 空余，十几种都放得下，不需要“语言包”。
- 生成的 `.c` 不手改，改源文件再运行脚本；提交时两者一起提交。

## 3. 字形

字形按 Unicode 码位找，不按语言：先找固件里的 Roboto，没有再找外部 Flash 里的字体包。所以多种文字可以同时用，
信道名里中英混排也一样。

| 文字 | 放在哪里 | 大小 |
|---|---|---|
| ASCII | 固件里的 Roboto，9 个字号（现在） | 87 KB |
| Latin-1（西、法、德、葡等的带音调字母） | 加到固件里的 Roboto | 约 20–87 KB |
| 中文（GB2312 全部，17 px；一级字 32 px 粗体） | 外部 Flash 字体包（现在的 `cjk.bin`） | 2.63 MB |
| 韩文（常用 2350 个音节，17 px） | 外部 Flash 字体包 | 约 330 KB |
| 日文（假名已在 GB2312 里；日本独有的汉字约 1000 个，17 px） | 外部 Flash 字体包 | 约 140 KB |
| 阿拉伯文（约 300 个字形） | 外部 Flash 字体包 | 约 40 KB |

外部 Flash 的字库区（0x280000–0x630000）共 3.69 MB，中文用了 2.63 MB，还剩约 1.05 MB：韩、日、阿拉伯文的 17 px
都放得下，大字号放不下的退回 17 px（现在中文二级字就是这样）。

要做的：

- 把 `cjk.bin` 推广成“字体包”格式：每套字体写明覆盖的码位范围、字号、粗细，可选地写明语言；去掉最多 4 套的限制
  （`font_cjk.c`、`tools/fonts/mkcjk.py`）
- **按语言优先**：中日文共用汉字码位，同一个码位只有一种字形。字体包标了语言时，界面语言相同的那套优先，日文
  界面里的汉字用日文字形
- 写字库放进 CPS（现在要用 `tools/fonts/upload_cjk.py`），用户按需写入要用的字体包

## 4. 码表里的名字

信道、区域、联系人的名字是 GB2312，16 字节。中文、英文、日文假名都够用，暂时不动。韩文名字等以后换编码（比如
码表整体标记为 UTF-8，由 CPS 转换）才支持；UTF-8 下 16 字节只能放 5 个韩文或汉字，这个限制要在界面和 CPS 里说明。

## 5. 从右往左的文字

阿拉伯文、希伯来文从右往左写，阿拉伯字母还要按在词里的位置变形。现在不做，但不要堵死：所有文字都经过同一个
绘字函数（`font_draw_text()`），以后在那里加双向排序和变形；界面左右镜像是另一步。

## 6. 分阶段

| 阶段 | 内容 |
|---|---|
| 1 | 语言编号和多语言菜单（第 1 节）；新的语言源文件格式和生成脚本的检查（第 2 节）；加西班牙文，中文保留 |
| 2 | 固件字体加 Latin-1：西班牙文等的带音调字母 |
| 3 | 字体包格式和按语言优先，CPS 写字库；韩文、日文 |
| 4 | 从右往左的文字 |

## 怎么帮忙

- **翻译**：复制一份英文源文件，改成你的语言，运行 `py tools/text/gen_text.py`，看它报的缺条目和超宽，在电台上
  每个界面看一遍，开 PR 到 `develop`
- **写代码**：上面的阶段按顺序做，开工前在 issue 里说一声，免得重复
- PR 的说明里写清楚在电台上看过哪些界面
