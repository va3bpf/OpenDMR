# NXDN

OpenDMR 的 NXDN 研究和实现（分支 `feature/nxdn`）。只按公开规范（NXDN TS 1-A 等）自己实现，不用 GPL 代码。

## 目录

| 路径 | 内容 |
|---|---|
| `py/demod.py` | IQ 录音（48 kHz 双声道 wav）→ FM 鉴频 → 找帧同步字（FSW 0xCDF59）→ 每帧单独定时、按 FSW 定电平 → `<wav>.frames.npy` |
| `py/frames.py` | 去扰码（X⁹+X⁴+1，每帧从 0x0E4 开始）→ LICH（7 比特 + 偶校验）→ 4 个 VCH（72 比特，和 DMR 的 AMBE+2 帧比特顺序相同）→ 我们的声码器（`vocoder/py`）解成 WAV |
| `py/l2.py` | SACCH / FACCH1：解交织、去打孔、软判决 Viterbi（K=5，G1 = 1+D³+D⁴，G2 = 1+D+D²+D⁴）、CRC6 / CRC12（初值全 1）；层 3 消息（VCALL、TX_REL、PROP_FORM）。`python nxdn/py/l2.py` 自测 |
| `py/tx.py` | 发射方向：AMBE 帧 + 主叫 / 组号 / RAN → 常规组呼（前导、第一帧两个 FACCH1 带 VCALL、语音帧带 SACCH 超帧、最后一帧和第一帧一样是非超帧 SACCH、两个 FACCH1 带 TX_REL）→ 加扰 → 4FSK（平方根升余弦 α=0.2 + 一个符号的保持）→ 48 kHz IQ；可加噪声（`--snr`）和载波频偏（`--offset`） |
| `py/chip.py` | 电台物理层抓到的符号（`p25_phy.py --dibits`，4800 符号/秒）按 NXDN48 分析：每块电平分布、两个采样相位、和发送的帧逐符号比对（`--reference`）、解 LICH / SACCH / VCH |
| `py/pi.py`、`py/pi_switch.py`、`py/run_alt.py`、`py/sweep.py` | 树莓派热点（Pi-Star + pistar-signal-gen）：ssh 控制（地址、密码只放环境变量 `PISTAR_HOST` / `PISTAR_PASS`）、P25 / NXDN 交替发射、交替发射同时在电台上抓取、增益和频偏扫描 |
| `py/radio_tx.py`、`py/radio_pair.py`、`py/chip96.py`、`py/patterns.py` | 电台对电台的 NXDN96：固件 `p25_phy_tx_test(..., 1)` 循环发 `p25_phy_tx_loop` 里的符号；先让接收端开始抓、发射时写频线保持安静、发完再读回；按 4800 符号/秒分析；简单图样帧 |
| `py/tx_test.py`、`py/hs_sweep.py`、`py/hs_trace.py`、`py/hs_compare.py`、`py/tx_level.py`、`c/check_tx.py` | 固件发射的测试：两台电台一发一收看计数器；热点（MMDVMHost 开 NXDN）收我们的信号，扫参数看日志；从 MMDVMHost 的调制解调器跟踪里取帧、找 FSW、和我们发的帧逐比特比；用另一台电台的鉴频器量频偏；电脑上编译固件的发射部分和 `tx.py` 逐符号对比 |
| `py/probe_l2.py` | 排查用：各种交织、打孔、抽头顺序的组合，看哪种和录音对得上 |
| `data/` | 下载的规范 PDF 和录音，**不进仓库**（`.gitignore`）：`spec/NXDN-TS-1-*.pdf`（qsl.net/k/kb9mwr 的镜像）、`iq/NXDN48 IQ.wav`、`iq/NXDN96 IQ.wav`（sigidwiki.com 的 NXDN_IQ.zip） |

## 用法

```
python nxdn/py/demod.py "nxdn/data/iq/NXDN48 IQ.wav" 2400
python nxdn/py/frames.py "nxdn/data/iq/NXDN48 IQ.wav"
python nxdn/py/demod.py "nxdn/data/iq/NXDN96 IQ.wav" 4800
python nxdn/py/frames.py "nxdn/data/iq/NXDN96 IQ.wav"
```

输出 `<wav>.decoded.wav`（解出的声音）和 `<wav>.bit`（AMBE 帧，9 字节一帧，可以用 `vocoder/py/decode.py` 再看）。

## 规范里的要点（TS 1-A Ver.1.3）

- 4FSK：dibit 01 → +3，00 → +1，10 → −1，11 → −3。NXDN48（4800 bps）2400 符号/秒，+3 = 1050 Hz；NXDN96（9600 bps）
  4800 符号/秒，+3 = 2400 Hz。
- 一帧 384 比特 = 192 符号（NXDN48 80 ms，NXDN96 40 ms）。语音帧：FSW 10 符号、LICH 8、SACCH 30、VCH 4 × 36。
- FSW 之后的 182 个符号都加扰：PN 输出 1 的符号取反。寄存器 S8…S0 初值 0 1 1 1 0 0 1 0 0，输出 S0，S0 ⊕ S4 移入 S8
  （另一种接法 LICH 也对，但语音全错）。
- LICH：每比特一个符号（0 → +3，1 → −3），7 比特 + 前 4 比特的偶校验。常规系统的语音帧是 `1010 11 x`（x：0 电台发出，1 中继发出）。
- EHR 语音：AMBE+2 3600/2450，每 20 ms 49 比特语音 + 23 比特纠错 = 72 比特。测试向量：1031 Hz 单音 `CEA8FE83ACC458200A`，
  静音 `B9E881526173002A6B`（和 DMR 的静音帧相同）。

## 现状

- 2026-11-16：两段录音解码成功。NXDN48（中继）512 个语音帧，34 位纠错；NXDN96（直通）704 个语音帧，0 纠错。
- 2026-11-16：SACCH / FACCH1 解码，CRC 几乎全部通过（NXDN48 SACCH 131/131、FACCH1 6/6；NXDN96 SACCH 349/353、FACCH1 346/350）。
  NXDN48：VCALL 组呼 901 → TG 0，RAN 1，4800 EHR，明文，还有厂家 0x68 的 PROP_FORM（分 4 段，带文字 "REPEATER"）；
  NXDN96：VCALL 组呼 2 → TG 0，RAN 0，9600 EHR。通话结束是 TX_REL。
- SACCH 超帧：4 帧各带 18 比特，SR 的结构字段 11 / 10 / 01 / 00 依次是 1/4 … 4/4，拼成 72 比特（9 字节）的消息。
- FACCH1：LICH 的偷帧标志（option 两位）说明哪一半是 FACCH1（11 都是语音，10 后半、01 前半、00 两半都是 FACCH1），
  每个 FACCH1 占两个 VCH 的位置（72 符号）。
- 2026-11-16：反向实验。`tx.py` 用录音里的 AMBE 帧生成 1234 → TG 9、RAN 1 的 NXDN48 / NXDN96 信号，`demod.py` + `frames.py`
  解回来：LICH、SACCH、FACCH1 全部通过，语音帧逐比特相同。加噪声（信道带宽内）和 +300 Hz 频偏：

  | 信噪比 | NXDN48 | NXDN96 |
  |---|---|---|
  | 20 dB | 全部通过 | 全部通过，语音 0 误码 |
  | 12 dB | 全部通过，语音误码 0.9 % | 全部通过，0.13 % |
  | 10 dB | 全部通过，1.8 % | 全部通过，0.5 % |
  | 8 dB | 丢 1 帧（同步字没找到） | 丢 1 帧 |
  | 6 dB | 丢不少帧，FACCH1 解不出 | 丢不少帧 |

  8 dB 以下主要是同步字检测（相关度门限 0.9、没有按帧间隔预测）先失败，可以改进。语音误码从丢帧开始错位，表里只列到对齐的部分。
- 还没做：用独立的解码器（比如 dsd-fme，只当黑盒工具用）核对 `tx.py` 的输出；电台上的物理层（HR_C7000 能否跑 2400 符号/秒）。

## 电台接收实验（2026-11-16 晚，HR_C7000 物理层，热点发 NXDN48 1031 Hz 测试信号）

工具：`tools/debug/p25_phy.py capture` 加了 `--sync`（任意 48 比特同步图样）、`--gain`（`RF_MODE[23:16]`）、`--threshold`
（`THRESHOLD_VALUE`）。实验用的固件把 `P25_PHY_BLOCKS` 改成了 160（4.8 秒，`src/services/p25_phy.h`，未提交，只为实验）。

- **能解出来**：芯片按 4800 符号/秒采样，NXDN48 每个符号采两次，取其中一个相位就是 NXDN 符号。先用 P25 同步锁住（热点交替发
  P25 / NXDN，`run_alt.py`），再把 `RF_MODE[23:16]`（af_recv_ctrl，手册说只用于 AF 模式，实际在中频模式也起作用）从 DMR 的
  0x26 调到 **0x36**：符号错误约 2 %（幅度 4.5 %），LICH、SACCH CRC 全对，VCH 正好是 1031 Hz 向量 `cea8fe83acc458200a`。
- 增益 0x26（DMR 原值）时 NXDN48 的 ±3（1050 Hz）大多被判成 ±1：正负号对，幅度错，语音解不了。
- `THRESHOLD_VALUE` 是同步检测门限（手册：[28:24] 比值门限 9、[23:16] 低门限、[15:8] 高门限 0x78、[7:0] sig_cor_value 0x6F），
  不是四电平判决门限。DMR 值下 NXDN 图样（同步字 + LICH 前 2 个符号，每个重复一次：`F0F5FF55A5F5`）不触发；**0x0140402F**
  时 NXDN 图样触发、随意的错误图样不触发。
- **没解决**：用 NXDN 图样锁定后，所有符号整体下偏一个电平（+3→+1、+1→−1、−1→−3），和热点频率（0 / +200 / +360 Hz）无关，
  4 次都一样；用 P25 锁定、或门限放很宽碰巧锁在随机数据上时，有时好有时坏。像是芯片锁定时用同步段估的直流 / 电平基准和
  NXDN48 不合。还要试：锁定后再改增益、`SIG_CENTER` 的接收偏置、`RX_IF_FREQ`（0xBB800，单位 Hz）微调、不同的同步图样
  （只用外侧 ±3 符号）、锁定后读 `PHASE_OUT`。
- 热点：Pi-Star 配置里 TXOffset = 360 Hz；pistar-signal-gen 发射时不加这个补偿。ssh 上 sudo 一来一回 4–5 秒，掐时间的实验
  用交替发射（`pi_switch.py` 每段之间先回空闲、等 TX 关掉，板子才会按新模式重新设调制）。
- 抓到的数据在 `nxdn/data/radio/`（不进仓库）：`cap_alt*` / `sw_*`（P25 锁定）、`self*` / `lock*`（NXDN 门限锁定）。

## 电台对电台 NXDN96（2026-11-17）

- 先做 NXDN96（4800 符号/秒，和芯片原生速率一样，不用重复采样）。热点（MMDVM）只发 NXDN48，所以发射端用另一台 DM-32：
  固件加了物理层发射的循环模式（`p25_phy_tx_loop`，768 符号），频偏是芯片自己的（+3 = 1944 Hz，真 NXDN96 是 2400 Hz）。
- 两个坑：① 两台挨着、50 mW 发射时，射频窜进接收那台的写频线，串口乱码、调用失败——发射期间写频线不能通信
  （`radio_pair.py`：先让接收端开始抓，再发，发完再读）；② 接收省电（`settings.eco_level`，默认 1，空闲 10 秒后开关接收机）
  打乱物理层接收：实验时写 0（`settings` + 0x65），做完改回 1。
- **关键发现**：芯片锁定时，按同步段里**实际收到的信号**估直流 / 电平基准，而且把同步段当成全是 ±3。DMR、P25 的同步字只有 ±3，
  没事；NXDN 的同步字有 ±1，锁在「同步字 + LICH + SACCH」上，之后所有电平下偏半格（+3→+1 26 %、−1→−3 34 %）。
  同步寄存器里把 ±1 写成 ±3 也一样（估计用的是实际信号）。验证：自制帧里放 24 个只有 ±3 的符号做同步，锁定后符号错误 1.08 %。
- **能用的办法**：常规通话开头的**前导**（12 个符号 0x5775FD，全是 ±3）+ 同步字 + LICH 前 2 个符号做同步图样
  （测试帧：`5775FDCDF59D`）：符号错误 2.68 %，LICH 59/59，SACCH CRC 57/59，VCH 224/236 正好是 1031 Hz 向量。只能在通话开头锁定
  （之后物理层一直连续出数据），中途加入的通话还锁不上。
- 下一步：真 NXDN96 的频偏（2400 Hz，接收增益相应调低，约 0x1F）；NXDN48 用同样的前导思路（前导在 2400 符号/秒下每个符号重复
  两次，正好 24 个）；中途加入；固件里的接收（解帧、声码器播放）。

## 同步窗口的实验（2026-11-17 白天，电台对电台 NXDN96，自制帧）

- 「芯片把同步段当成全 ±3 来估计」的推测**不对**：窗口里任意位置放 ±1（W2–W5、末尾、开头、照帧头的位置）锁定后都 100 % 正确。
- 「芯片锁偏位置」也不对：真实帧头锁定时，锁定块同步位置上的符号正负号都对，只是**整体下偏一个电平**——锁定时估出的电平基准
  偏了。和内容有关：真实帧头的 24 个符号放到同步字之后照样坏；二分到第 0、7、10、11、12 位**共同**作用（单独换哪一半都好）；
  旁瓣、按半求和都解释不了，芯片内部怎么估的反推不出来。
- 其他排除的：±1 在寄存器里的编码（00 = +1、10 = −1 是对的，对调就锁不上）；`RF_MODE[25]` phase_avg_en、[31]/[29]；放宽门限
  （锁在随机数据上，锁定块的已知符号只对 1–9 / 18）；发射块开头的毛病（循环 768 不是 144 的倍数，位置会漂）。
- 注意：`RF_MODE` 在 DM-32 上是 0x03269860，`af_mode`（[24]）= 1，用的是 AF 模式，所以 `af_recv_ctrl` 增益起作用。
- 工具陷阱：`p25_phy.py` 按 `RX_TYPE_INFO[1:0]` 还原每块的顺序，改动块记录（type / us2）会让还原全错。锁对时，NXDN96 的图样每 4 块
  在同步位置再出现一次（类型 2），80 块里 20 块；锁偏时只有锁定块是类型 2。
- 能用的：**前导**锁定（标准里常规信道每次发射开头都有，全是 ±3）。锁定后物理层一直连续出数据，整个通话不用再锁；中途加入还没解决。

## NXDN48 从热点直接锁定 / 软件解调的尝试（2026-11-17 下午）

- 热点（MMDVM_HS）发射开头有长前导 +3 +3 −3 −3（`55FF55FF55FF` = 每个符号重复两次后的图样能锁上）。但长前导经过成形接近
  600 Hz 正弦，芯片从它定不准采样时刻：锁定后最好一次（增益 0x36）正负号错误 5.5 %、幅度 9.4 %，不稳定。5775FD 图样锁不上。
- 参考 DM32-nxdn-p25（GPL-3.0，只看了文档 `docs/nxdn-modem.md`、`docs/modem.md`，没有看代码）：它的思路是**不用芯片的 4FSK
  解调器**，电台处在 FM，FD6818 的平坦鉴频输出（0x2B = 0x0700 关掉 300 Hz 高通、3 kHz 低通、去加重）进 HR_C7000，CPU 读 8 kHz
  录音，软件做匹配滤波、Gardner 定时、电平 / 直流跟踪、两种极性找 FSW。
- 我们试了 HR_C7000 的「模拟接收录音」（手册：`WORK_MODE` bit 7 FM，RX RAM 0x160004E0 – 0x160008DF 两个半区各 256 个 16 位采样，
  `FM_ADDR_SW`（0x56C）指出可读的一半；固件实验函数 `nxdn_af_capture()`，`nxdn/py/af_capture.py`、`af_demod.py`）：
  - 录音的两个半区接得上（乒乓读法对），但数据只有约 8 位精度（低字节为 0）。
  - FD6818 用 DMR 设置（0x50 = 0xBB20）时 FM 录音没有输入（只有每 64 ms 一个冲激经带通的振铃）；电台切 FM、0x2B 改 0x0700、
    `FM_BANDWIDTH` 0x0F（关带通、预加重）后有输入，但 `fm_dev_coef_r`、`af_recv_ctrl` 怎么调都只有几到二十几个量化台阶，
    频谱是平的噪声，看不到 4FSK。FD6818 的鉴频信号从哪个脚、什么设置送进 HR_C7000 的 FM 录音，还没弄清。
- 调试接口的 FD6818 读写（`'D' 'r'`）没实现；用 `x` 调 `fd6818_read` / `fd6818_write` 可以。

## NXDN48 用软件解出来了（2026-11-17 傍晚，FM 录音通路）

思路参考 DM32-nxdn-p25 的文档（只看文档）：不用芯片的 4FSK 解调器，取鉴频音频在软件里解调。在我们这里能用的组合：

- **FD6818 保持 DMR 设置**（0x50 = 0xBB20：把平坦的鉴频基带送进 HR_C7000；0x2B = 0x0700）。电台切 FM 时 HR_C7000 的
  FM 录音里**没有** FD6818 的音频（1 kHz FM 单音测试：录不到）。
- HR_C7000 临时切 FM 录音（`WORK_MODE` 0x80），**`FM_BANDWIDTH` 0x1F**（bit 6 带通关，bit 4 去加重开）。0x5F 在 300 Hz 以下
  陡峭切掉（200 Hz 低约 70 dB），4FSK 不能用；bit 4 关的（0x0F、0x4F）噪声淹没信号。`FM_DEV_COEF` 用 0x40A25（系数 0x0A）。
- 录音：RX RAM 0x160004E0，两个半区各 256 个采样，**16 位大端**（1 kHz 单音按大端读 80 % 纯，小端 13 %），8 kHz；
  `FM_ADDR_SW`（0x56C）指出可读的半区。切换后先等 0.6 s：FM 通路的隔直从很远处回来要约 0.3 s。
- 抓取期间 `dmr_sound.c` 会按 `p25_phy_work_mode` 改回 `WORK_MODE`：抓取函数临时把它设成 FM（修好后 1200 Hz 单音 5/6 次 100 % 纯）。
- 软件：8 kHz → 24 kHz，**反去加重**（x + τ·dx/dt，τ ≈ 530–750 µs），低通，按 FSW 找帧（两种极性、20 个相位），每帧按 FSW
  定时、定电平（`af_demod.py --tau 750`）。
- 结果（热点 NXDN48 1031 Hz 测试信号，−66 dBm）：符号正负号错误 3.1 %，幅度 5 %，11 帧里 SACCH CRC 10，语音帧 40/44 正好是
  1031 Hz 向量。有一次 τ ≥ 750 µs 时选错了相位 / 极性（解调脚本的选法要改）。
- 工具：固件 `nxdn_af_capture()`（p25_phy.c，`nxdn_af_settle_ms`、`nxdn_af_rewrites`），`af_capture.py`、`af_demod.py`、
  `fm_response.py`（另一台电台发 FM 单音量频率响应）、`fm_sweep.py`。测试频率用 UHF（VHF 有电脑干扰）。
- 还要做：录音偶尔整段是常数（第一次抓取常这样）；更好的匹配滤波 + Gardner 定时；去加重时间常数精确测出来；NXDN96 走同一条路；
  移到固件里实时做（8 kHz 采样的中断 / 任务，整数运算）。

## 热点做基准：DMR 对照 NXDN48（2026-11-17 晚，hs_ab.py）

- 热点发 DMR 测试信号（TS1），芯片按 DMR 同步抓物理层：6 个语音突发 0 比特错误（`dmr_check.py`），80 块里 40 块重新同步。
  抓取 / 还原工具可靠。
- 同一环境改发 NXDN48：真实帧头图样 `F0F5FF55A5F5` 锁定，符号错误 38–45 %；热点频偏 −400 / 0 / +400 Hz 结果一样（芯片直流跟踪没问题）。
- 自制 NXDN48 帧（`hs_ab.py`）：FSW 后放 12 个符号做同步（重复采样后正好 48 位），帧剩下的是电平阶梯。同步段只有 ±3 时符号错误
  仍有约 24 %，所以不是同步字长度的问题。
- 错误的样子每次锁定都不一样：增益 0x2E 时正半边被压（+3→+1），0x32 / 0x36 时负半边被压（−3→−1），真实帧头锁定时 +3 会翻成 −3。
  也就是锁定那一刻估出的电平基准 / 判决门限每次不同，之后很少重新同步（80 块里 1–10 块，DMR 是 40 块），错的基准就一直用下去。
- 原因判断：芯片的匹配滤波、定时恢复、电平估计都是按 4800 符号/秒的 DMR / P25 设计的。NXDN48 是 2400 符号/秒，一半采样点落在符号
  过渡上，估计有偏，而且只在锁定时估一次。NXDN48 走芯片物理层这条路不可靠，**接收走 FM 录音 + 软件解调**（已经做到约 3 % 符号错误）。

### 从 DMR 一步步变到 NXDN48（dev_sweep.py、dmr_ab.py、hs_ab.py）

- **陷阱**：`p25_phy.py capture` 之后电台的普通 DMR 接收不再工作（换增益 / 同步寄存器后没恢复），之后的抓取也受影响。现在每次抓之前
  重启电台（`dev_sweep.fresh()`，重启后 eco 要重新关）。本节之前那些"频偏无关"、"增益 0x36"的结论都是在这种状态下得到的，不可信。
- 热点 DMR，每次只改一个变量，芯片用 DMR 同步：
  - 载荷每个符号重复两次（2400 符号/秒）：0 误码 → **速率不是问题**。
  - 发射电平（调制频偏）128 / 115：0 误码；100 / 85 / 70：普通 DMR 也收不到，物理层锁不上 → **芯片对调制频偏只容忍约 10 %**。
  - 加增益补偿（`RF_MODE[23:16]`）：电平 100 → 0x2C，85 → 0x32，70（≈ NXDN48 频偏）→ 0x42 – 0x4C 都是 0 误码。
  - 重复两次的载荷 + 电平 70 + 增益 0x46：0 误码。
- 频偏标准值：DMR ±1944 / ±648 Hz，P25 ±1800 / ±600（93 %），NXDN48 ±1050 / ±350（54 %），NXDN96 ±2400 / ±800（123 %）。
- 回到 NXDN48（增益 0x46）：正负号错误降到 2–6 %，但还有一侧电平错一格，方向随每次锁定变化，频率改 ±360 Hz 没有规律
  （每个条件只抓了一次，需要重复测方差）。和上面 0 误码的 DMR 情况相比，剩下的不同：同步图样（重复采样的 NXDN 图样 vs DMR 原生
  同步字）、重新同步频率（DMR 空闲时隙每 60 ms 一次数据同步，80 块里 40 块；NXDN 1–10 块）、热点 NXDN 的成形滤波。
- 第 1 步（重复 4 次，增益 0x46）：outer 符号错误 18–26 %，fswlich 24–31 %，正负号错误 2–7 %；80 块里通常只有 1 块重新同步。
- 第 2 步：一帧 3 个图样（每 128 个芯片符号）没有改善（20–54 %）。图样严格每 144 个芯片符号（一个 30 ms 块）出现一次（`outerP`，
  3 帧一个循环）：符号错误 **4.7 % / 14.8 % / 5.6 %**，正负号错误 0.1–1 %。剩下的主要是 −3 → −1（15 %）。但重新同步的块数
  （类型 2）有时 1、有时 80，和误码没有对应关系，所以"必须按 30 ms 重新同步"还不能下结论。P25 的 LDU 864 符号正好是 144 的 6 倍。

## FM 录音通路的稳定性（2026-11-17 晚，`af_stability.py`）

- 热点 NXDN48 1031 Hz 测试信号，`FM_BANDWIDTH` 0x1F，反去加重 τ = 600 µs。每次重启电台：**10/10** 次录音正常（没有整段常数），
  正负号错误 0.2 – 4.1 %，LICH 全对，SACCH CRC 104/106，语音帧 405/432 是 1031 Hz 向量。不重启连续录：**6/6** 正常，0.8 – 3.7 %。
- 以前"偶尔整段是常数"多半是物理层抓取弄乱了接收状态（当时没有每次重启）。
- 误码在 0.2 % 和 4 % 之间来回，是软件解调的问题（每帧只按 FSW 定时、定电平），下一步：匹配滤波、Gardner 定时、电平跟踪。
- **更正**：那 0.2 – 4 % 的误码全部来自录音末尾那一帧不完整（录音在帧中间结束，后半帧是垃圾）。`af_demod.py` 改成只解完整的帧后，
  10 段录音 98 帧：正负号错误 0 – 0.1 %，LICH、SACCH CRC 全对，语音帧 392/392 中 391 是 1031 Hz 向量。`af_eq.py analyse`：
  按已知符号拟合后噪声 rms 0.35（电平间隔 2），帧内各位置都没有成片的错误；每帧的直流偏移在 +220 … +430 之间变（FSW 定偏移够用）。
  强信号（−66 dBm）下现在的软件解调已经够用，不用先做 Gardner / 均衡。

## 固件里的 NXDN48 接收（2026-11-17 晚，能出声）

- 信道模式 NXDN（`CODEPLUG_MODE_NXDN` 6，写频数据里存成数字信道 + `opendmr_mode` 0xA5），模式键在 P25 之后。
- 通路：FD6818 保持 DMR 设置，HR_C7000 切 FM 录音（`afrec_start()` / `afrec_read()`，p25_phy.c：`WORK_MODE` 0x80，
  `FM_BANDWIDTH` 0x1F，`FM_DEV_COEF` 0x40A25，DMR 的中断处理让开）→ `nxdn_core.c`（解调、找帧、解帧）→ `nxdn_radio.c`
  （通话、主叫 / 组号 / RAN 显示、最近呼叫）→ 我们的 AMBE+2 解码器 → 提示音 FIFO 播放（调制解调器一直在 FM，不能用 DMR 的播放通路）。
- **CPU 没有浮点单元**（浮点乘法约 1.6 µs，整数乘加 0.03 µs）：`nxdn_core.c` 全部定点（采样 int32，时间 Q12，符号 Q8），
  只有低通滤波器系数在初始化时用一次浮点。接收时整体约 18 % CPU（AMBE 解码每帧约 2.7 ms）。
- 找帧：FSW 相关度 > 0.85 后再看满一帧，留 3 个候选，逐个试解，LICH 和 SACCH CRC 都过的才锁定（测试信号帧尾的 10 个符号
  和 FSW 几乎一样，只看相关度会早锁 10 个符号）；都不过就不锁（噪声里常有像 FSW 的 10 个符号）。通话必须从 SACCH 或 FACCH1
  CRC 通过的帧开始。
- **播放**：提示音 FIFO 每 1 ms 最多写一块（16 个样本）。一次连写几块会写溢出（"满"标志来得晚），丢样本，声音抖动、有冲击声。
  预缓冲 6 帧（语音每 80 ms 来 4 帧）。
- 实测（热点发 DVSI r33 `clean.bit` 74 秒）：每秒 12.5 帧全收，SACCH 全过；语音帧误码约 1.4 %（`vch_check.py`），8 % 的帧
  错 3 位以上，听感可以。以后可改进：均衡 / 匹配滤波（`tap_grab.py` 抓接收录音，`tap_ber.py` 在电脑上量误码）。
- 我们自己的 AMBE 编码器编 THCHS-30 D11 那段时有冲击声（电脑上解码也有）：测试语音用 DVSI 编好的帧。
- 工具：`nxdn/c/run.py`（电脑上编译 `nxdn_core.c` 跑录音）、`nxdn_stats.py`（计数器）、`vch_check.py`、`tap_grab.py`、
  `tap_ber.py`、`make_voice.py`（WAV / .bit → 热点帧文件）、`flash_play.py`（AMBE 帧写进 flash 调试区 0x410000 循环播放，
  测解码和播放通路；DMR ID 数据库在 0x5AF000 – 0x8FF000，别碰）。
- 还要做：按键提示音和 NXDN 语音共用 FIFO；NXDN 下省电关着（发射、RAN 过滤、CPS 支持、底栏 6.25K 见下面两节）。

## 固件里的 NXDN48 发射（2026-11-17，热点误码率 0 %）

- 编码：`nxdn_core.c` 的 `nxdn_tx_*`（帧、LICH、SACCH、FACCH1、VCH、VCALL / TX_REL），在电脑上和 `tx.py` 逐符号相同
  （`c/check_tx.py`）。按 PTT：停录音，话筒每 20 ms 一帧进我们的 AMBE+2 编码器，4 帧一个 NXDN 帧；每个符号重复两次，
  送进 P25 物理层的发射 FIFO（芯片 4800 符号/秒）。前导之前先发 144 个 +3 / −3 符号（60 ms）：第一帧语音要 4 帧话筒
  加编码约 95 ms 才有，中断又提前 30 ms 取一块。松开：用静音补满这一帧，发结束帧，回到接收。
- 内存：编码器那条路径的栈实测约 6.1 KB（`-fstack-usage`），任务栈 7 KB；发射缓冲区和接收的半块缓冲放进声码器的 overlay。
- **频偏**：`RF_MOD_BIAS_CTRL` 的低 16 位是**两个字节**，要各自缩放（`modem_set_mod_scale()`）。0x4343 是 DMR / P25 的电平
  （+3 = 1944 Hz）；0x2424（`nxdn_tx_dev` 553 / 1024）在另一台电台的鉴频器上和热点自己发的 NXDN48 一样大（`tx_level.py`）。
  一开始按一个 16 位数缩放成 0x2452，频偏反而**更大**，热点 ±1 符号几乎全错、什么都解不出；我们自己的接收端能收（按 FSW 拟合电平），
  所以看不出来。
- 极性是标准的（`p25_phy_tx_xor` 0）。频偏错的时候反相"能收到几帧"，是假象。
- **结束帧**：MMDVMHost 只在非超帧 SACCH 的帧里认 VCALL / TX_REL；结束帧原来用 LICH 0x50（超帧 SACCH + 两个 FACCH1），
  热点记成 "transmission lost"，改成和第一帧一样的 0x40 后："received RF end of transmission ... BER: 0.0%"。
- 热点测试的做法：备份 `/etc/mmdvmhost`，RXFrequency 改成电台的频率，`[NXDN] Enable=1`、`[DMR] Enable=0`、`Duplex=0`，
  要看调制解调器上报的帧再开 `[Modem] Debug=1`、`Trace=1` 和 `[Log] FileLevel=1`；测完恢复。Pi-Star 的根文件系统会自己变回
  只读（改之前 `mount -o remount,rw /`）；日志是 UTC 时间，`date` 是本地时间。

## NXDN 的设置（2026-11-17）

- **RAN**（0 – 63）每个信道 / VFO 一个，存在 DMR 色码那个字节（`codeplug_nxdn_ran()`，超出范围当 1；OpenGD77 CPS 写的信道
  就是它的色码）。接收只收相同 RAN 的（0 收全部，`nxdn_radio_stats.other_ran` 计不同 RAN 的帧），发射用这个 RAN。
- **个呼**：联系人是个呼（ID ≤ 65535）就发 call type 4；收到发给别的 ID 的个呼不放音。超过 16 位的组号 / 联系人改发组 1。
- **NXDN ID**（16 位，和 DMR ID 分开注册）：常规设置里设，存在码表自定义数据块 "DT" 6（0x44540006：版本 1、0、ID 小端），
  CPS 也能改；没设时用 DMR ID（大于 65535 取低 16 位）。
- 界面：信道详情里色码一项变成 RAN，可以选组列表和联系人，亚音不适用，带宽 6.25kHz；信道、VFO、发射界面显示发射目标和 RAN；
  底栏 6.25K。CPS：模式 NXDN、RAN、CSV 的 RAN 列、常规页的 NXDN ID。
- 两台电台实测：RAN 1 的信号，接收端 RAN 1、0 都收，RAN 2 不收；发给接收端 ID 的个呼收，发给别的 ID 的不收。
- 用写频线测要注意：直接改 `nxdn_radio.c` 的 `tx_ran` 没用，界面每次刷新（比如收到信号）`tx_target_apply()` 都会改回去；
  要改 VFO 本身（`vfos[0]` 偏移 44 是 RAN）或 `settings.override_tg`（偏移 16，个呼在最高字节放 0x03），再按个键让界面刷新。
- 还要做：NXDN ID 到呼号的数据库；扫描时不同 RAN 的信号也会停（有信号的标记在 RAN 检查之前）；`nxdn_tx_low_power`
  只是调试变量。

## 延迟（2026-11-20）

通话一开始就打开功放、录音每 16 ms 读一次、接收时 VCALL 帧前后的锁定和超时修正，按键到出声从 440–614 ms 降到
约 290–300 ms。见 [docs/voice-delay.md](../docs/voice-delay.md)。

## 解调改进（2026-11-21，弱信号）

两台拔天线，COM23 50 mW 发 flash 里的 DVSI `clean.bit`（`flash_play.py write --port COM23`，`nxdn_tx_source` 1），
COM22 用 `tap_grab.py` 抓 40 段 256 ms 录音，电脑上 `tap_ber.py`（`nxdn_core.c` 同一份代码）和发的帧比误码。
两批录音：`w110_*`（−110 dBm，调参数）、`v110_*`（−115 dBm，验证）。

| | −110 dBm | −115 dBm |
|---|---|---|
| 原来（低通 1440 Hz） | 0.67 %，80 帧有错，3 帧错 3 位以上 | 0.82 %，87 帧有错，2 帧 |
| 每帧按判决重估电平（`fsk4_relevel`） | 0.43 % | 0.68 % |
| **低通 2000 Hz + 重估电平（现在）** | **0.06 %，9 帧有错** | **0.29 %，44 帧有错，0** |

- 1440 Hz 的低通太窄，码间干扰比放进来的噪声更伤；2400 Hz 以上又变差。
- DMR / M17 的三抽头均衡在这里更差（系数重新拟合后最多到 0.30 %，低通放宽后就不需要了）；根升余弦（α 0.2、0.35）
  也更差。
- 同步搜索：上次为了延迟改成"第一个超过门限、校验通过就锁定"，在 −115 dBm 下有一段锁在了帧内容里像同步字的地方
  （相关 0.88，真同步字 0.99），整段解错。现在相关 ≥ 0.95 才马上试解，否则在一整帧里挑最好的（原来的做法）。
- 实机（−114 dBm）：最近 256 个语音帧平均每帧错 0.18 位；按键到出声仍是 286–304 ms。
- 测试参数：`NXDN_OPT`（1 重估电平）、`NXDN_LP`（低通 Hz）给 `test_core.exe` / `tap_ber.py`。
- 复核（同日，修了 FD6818 切过 SSB 后中频为 0、AFC 关着的问题之后，`c110_*`，−113 dBm）：有信号的部分低通 1440 +
  重估电平 36 个错比特 / 208 帧，低通 2000 + 重估电平 4 个；发射结束后的噪声里偶尔锁上一次、解出两帧乱码（1440 时没有）。
  前两批录音是在 FD6818 被切坏的状态下录的，结论不变。
